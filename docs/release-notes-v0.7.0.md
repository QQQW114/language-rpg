# v0.7.0 发行说明（2026-10-22）

本版新增 **灵魂共创模式（co_author）**：模型先读懂玩家给主角注入的性格与意图，顺着玩家的戏演，再把大纲节拍“顺势嫁接”进来；新旅程默认使用该模式，旧存档保持原有标准推进。

## 为什么做

玩家真实游玩 10 回合后发现：模型文笔很好，但 planner 总在按“任务表/节拍”推进——玩家选择“继续装死”，模型却替主角祈祷并自动变身；玩家已经“溜了”，模型还在回合末尾塞新 NPC；玩家一句冷幽默“跑饿了”，被写成异能反噬低血糖。Gemini 第三轮复审与存档逐条核对后，确认这是“任务驱动 planner 抢方向盘”，不是文笔问题。

## 新模式：灵魂共创（co_author）

- **推进权限四档**：严格跟随 / **灵魂共创（新默认）** / 主线推进 / 自由发散。旧存档缺失字段仍按“主线推进”迁移，不改变历史档行为。
- **先读灵魂再规划**：planner_pre 新增 `soulAndIntent`（主角灵魂、玩家本轮意图、语调、避雷边界）；story 注入 `【SOUL_AND_INTENT】`。
- **允许零节拍**：co_author 下 `beatsThisTurn` 可为 0~1；玩家离场/独处/收尾时允许 `[]`，不强行换场景塞新角色。
- **主角意志归玩家**：story 硬规则禁止代写主角决定/祈祷/变身；禁止“没有 A 的…也没有 B 的…”防御性免责旁白；玩家冷幽默按同语调承接，世界书硬设定优先，禁止自行发明 debuff/反噬；尊重玩家指定 POV/分镜。
- **灵魂画像持久化**：`soulProfile`（≤120 字）随 planner_post 更新、存档保留、注入三阶段，避免每回合回到“出厂小白兔”。
- **随机事件变情境催化剂**：co_author 冷却 3~5 回合；可主动跳过并顺延；禁止为补 pending beat 空投跨场景事件。
- **导出 meta**：导出的存档 JSON 增加 settings（无 Key/Base URL）、outlineId/backgroundId、finalStateSummary（含 soulProfile），便于复盘。

## 10 回合真实 A/B（gemini-3.8-flash-high × 错位青春，同一批玩家输入）

co_author vs 原始 standard：

| 验收项 | 结果 |
|---|---|
| T1 装死 | ✅ 不替玩家祈祷/自动变身，停在门被撬开一条缝，变身开关留给玩家 |
| T4 “传送室” | ✅ 通勤压成一句轻快过渡（未字面演超现实传送，列入 0.7.1 候选） |
| T6 保洁阿姨 POV | ✅ 阿姨段占 47.5%（原 33%），独立半场喜剧完整 |
| T8 十连变+觅食 | ✅ 明写“倒不是能力有什么消耗”；0 反噬编造、0 强制舍友催饭 |
| T10 “溜了” | ✅ 0 紫藤长廊新 NPC、0 防御性旁白；交集全部嫁接到 404 群聊乐子 |
| 程序 | ✅ 5/10 回合 `beatsThisTurn=[]`；随机事件 3 回合冷却 + T8 主动跳过；soulProfile 10/10 落盘；standard 3 回合回归未变 |

统计：10/10 回合、31/31 请求 200、总 20.2 min；co_author 字数 p50 1520 / max 1861（比原 standard mean +30%，pacing 全干净）；反代无缓存、单次采样、固定输入，数据只作方向参考。

## 测试

- 单元测试 **661/661**（24 个测试文件）；e2e **44/44**；build、test:patch 通过。
- 测试覆盖：co_author 文案/零节拍/soulAndIntent/坏值截断、soulProfile 落盘与注入、随机事件冷却/跳过/interrupted、导出 meta 无 Key、standard 回归。

## 已知问题 / 边界

- T4 的“传送室”超现实转场目前只做轻快压缩，不按字面演出；0.7.1 候选。
- T8 有一句路人 NPC 误诊台词“低血糖”，属台词非叙述事实；可保留。
- co_author 会把用户自定义随机事件冷却夹进 3~5 回合；极端自定义不再生效。
- 跟随模式可能让模型“不敢替主角做主”，需观察 NPC 是否过度被动；当前用“主角意志归玩家、外部世界鲜活反弹”对冲。
- 反代无缓存、gemini 单回合约 2 分钟；内容审核偶发误判，已有阶段重试/护栏。

## 兼容性

- 存档 schema 未变（`SAVE_STORAGE_VERSION = 2`）；新增字段均可选，旧存档无需迁移。
- 新旅程默认 co_author；旧存档保持原 `standard`，可在游戏页随时切四档。
- API Key 仍只保存在浏览器本地；导出 meta 不含 Key/Base URL。
