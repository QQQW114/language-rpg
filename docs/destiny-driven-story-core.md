# 命运驱动自由故事：核心产品定位与设计边界

> 本文是 V2 后续设计、提示词、程序状态与前端交互的最高层产品约束。若旧文档、旧实现或局部功能与本文冲突，以本文为准。

## 1. 一句话定位

这是一个**设定好核心命运与结局、但允许玩家自由改变抵达路径的 AI 互动故事系统**。

玩家既是故事中的主角，也是共同作者。系统不负责把玩家锁在固定路线中，而是负责让世界书设定的核心人物、矛盾、成长与结局，能够穿过玩家造成的路线变化，以新的合理形式继续发生。

```text
玩家行为改变路径
≠ 玩家行为取消世界命运
```

## 2. 不是什么

本项目不是：

- 纯开放世界模拟器；
- 以胜负、数值和平衡为中心的传统 RPG；
- 严格照搬固定章节与固定事件顺序的小说播放器；
- 对玩家行为进行许可判断、发现“越权”就拒绝的跑团裁判；
- 依靠大量 Agent、规则引擎和程序限制替代模型文学判断的系统。

程序不做“剧情警察”。除数据安全、格式校验和明确的世界硬规则外，不应为了阻止玩家改变路线而增加拦截、重试、截断或复杂状态机。

## 3. 固定的是命运功能，不是固定路线

世界书可以预设：

- 故事最终要抵达的结局；
- 主角必须经历的核心成长；
- 关键人物及其承担的命运作用；
- 必须完成的主要矛盾、关系变化或认知转变；
- 世界不可突破的硬规律。

但以下内容通常允许随玩家行为迁移或替换：

- 发生地点；
- 事件顺序；
- 事件的表面形式；
- 关键人物进入故事的方式；
- 承担某个剧情功能的具体场景；
- 抵达结局的时间与路线。

因此，系统要保存和推进的是“命运功能”，而不是机械复刻某一条剧本路径。

例如，玩家离开原学校、转学到外省，并不意味着校园命运线失效。规划模型应重新安排合理的汇合方式：关键角色可能因交流、搬迁、比赛、旅行、网络联系或其他符合世界规律的原因进入新舞台；原本由旧校园事件承担的成长功能，也可由新环境中的等价事件承担。

## 4. 玩家是共同作者

玩家可以主动改变故事：

- 前往世界书没有详细描述的地点；
- 主动认识新角色、建立新关系；
- 离开当前主线场景；
- 改变计划、身份或生活环境；
- 提出明显偏离当前路径的行动；
- 使用作者式输入推动时间、关系或事件。

系统不应将这些输入默认视为错误。

当玩家提出与世界硬规则不符的目标时，模型应依据世界书决定其**合理的实际结果**，而不是由程序机械拒绝。例如，现实世界中不存在玄幻宗门，玩家仍可转学、旅行并寻找宗门；故事可以将其解释为传闻、社团、文化组织、误会或其他现实存在，同时继续把核心命运带入这条新路线。

玩家的自由主要决定“怎么走”；世界书和长期目标决定“这段命运最终要走到哪里”。

## 5. 长期目标是命运吸引子

长期目标不是普通任务提示，也不是可被一次偏离永久取消的支线。它是持续作用于整个故事的“命运吸引子”。

规划模型每轮都应判断：

1. 玩家当前想做什么；
2. 当前路径与预设命运处于什么关系；
3. 本轮如何尊重玩家行动并产生真实后果；
4. 本轮事件如何提高故事完成度；
5. 若路径发生改变，关键人物、矛盾与事件功能如何自然迁移；
6. 下一次最合理的命运汇合机会是什么。

偏离不是异常，也不需要被立刻纠正。玩家的行动可以暂时降低主线推进速度，但世界发展和长期命运仍应继续。规划模型应寻找自然、渐进的汇合方式，而不是生硬地把关键角色或关键事件强塞到当前场景。

## 6. 双模型职责

### 6.1 写前规划模型

写前规划负责：

- 理解玩家意图；
- 读取世界硬规则、当前状态与相关上下文；
- 识别当前命运阶段与长期目标完成度；
- 判断路线变化，但不把变化定性为违规；
- 规划本轮如何尊重玩家选择；
- 安排长期目标的推进或未来汇合机会；
- 在触发时吸收随机事件要求；
- 按当前叙事速度给故事模型提供写作要求。

它不应以“玩家是否越权、是否允许执行”为核心问题，而应回答：

> 玩家改变了路线后，预设命运如何沿新路线继续实现？

### 6.2 故事模型

故事模型负责：

- 将玩家输入和写前规划写成自然正文；
- 尊重世界书硬规则和已经成立的上下文事实；
- 让玩家行动产生合理而非机械的结果；
- 根据叙事速度控制镜头尺度与时间跨度；
- 让事件、关系和环境变化服务当前阶段及长期命运；
- 保留必要的不确定性，不替程序维护结构化状态。

故事模型可以补全世界书未写明的细节，但已经在正文中明确成立并被保存的设定，后文应优先延续，不得随意改写。

### 6.3 写后规划模型

写后规划负责独立审阅本轮实际正文，并输出严格的增量状态变化：

- 最新故事摘要与进度；
- 人物、关系、好感变化；
- 道具获取与消耗；
- 任务或故事线程变化；
- 本轮新确认的长期设定；
- 当前命运阶段、完成度与路线变化；
- 尚未执行但未来可用的汇合机会。

写后规划只记录正文真实发生的内容，不把写前计划当成已经发生的事实，也不因玩家改变路线而给出“越权”裁决。

## 7. 程序职责与克制边界

程序应负责：

- 保存世界书、故事历史、摘要和结构化状态；
- 提供可靠的相关上下文；
- 校验并提交写后规划的结构化 Patch；
- 稳定人物、关系、线程和事实 ID；
- 防止格式错误、重复提交和明显的数据损坏；
- 保存叙事速度；
- 以轻量机制触发随机事件提示；
- 将长期目标稳定注入规划上下文。

程序不应负责：

- 判断玩家是否“有权”改变剧情；
- 因路线偏离而拒绝整轮状态；
- 通过复杂规则限制关系发展速度；
- 替模型判断每个剧情选择是否文学上合理；
- 为模型偶发的普通理解错误不断增加特殊兼容；
- 用硬编码路线把故事强制拉回原场景。

核心原则：

> 程序维护数据可靠性，不替模型做文学判断。

## 8. 随机事件：为命运服务的轻量提示

不恢复随机事件 Agent、复杂事件库或繁重调度系统。程序仅在若干随机回合向写前规划注入一条额外要求，并允许在本回合或下一回合自然兑现，避免为了完成指令而强塞事件。

随机事件必须与当前故事相关，不能只是无意义装饰。可使用三档要求：

### 8.1 严格相关

```text
---额外---
在本回合或下一回合自然插入一个与当前故事严格相关的随机事件。
事件应与当前人物、环境、关系或进行中的故事线程直接相关，不能成为脱离正文的一次性装饰。
```

### 8.2 严格相关且推进情节

```text
---额外---
在本回合或下一回合自然插入一个与当前故事严格相关的随机事件。
该事件必须推进至少一条当前故事线程、人物关系或现实处境，不能只是无后续影响的插曲。
```

### 8.3 严格相关且推进长期命运

```text
---额外---
在本回合或下一回合自然插入一个与当前故事严格相关的随机事件。
该事件必须推进长期目标或提高故事完成度，使当前自由路径获得新的命运汇合机会。
```

随机事件可以制造新的角色、环境与局部变化，但最终仍需服务故事完成度。随机不等于无方向。

## 9. 四档叙事速度

游戏页面应允许玩家在每轮输入前随时切换叙事速度。该选项控制模型的写作尺度与时间跨度，而不是简单改变输出 Token 数量；选择应随存档保存，并同时注入写前规划和故事模型。

### 9.1 慢叙事

- 细致到动作、感官、心理和短句对话；
- 一轮只推进很小的时间节拍；
- 适合关键对话、情绪变化、冲突现场和重要关系节点。

### 9.2 标准叙事

- 默认模式；
- 一轮完成一次主要行动或一个完整场景；
- 在细节与推进速度之间保持平衡。

### 9.3 快叙事

- 以事件发展为单位；
- 可连续完成一组直接相关的行动；
- 保留关键选择、结果和关系变化，略过重复过程。

### 9.4 时间跨越叙事

- 允许跨越数天或更长时间；
- 以概述和关键节点串联发展；
- 必须保留影响命运、人物关系、任务和硬状态的关键事件；
- 不应把尚未建立的长期变化无证据地直接写成既成事实。

## 10. 世界硬规则、路径自由与事实延续

三者优先级应明确区分：

1. **世界书硬规则**：定义世界真正允许发生什么，不因玩家输入直接失效；
2. **已确认的长期事实**：正文已经建立并由写后规划保存，应在后续持续延续；
3. **自由路径与临时补全**：玩家和模型可以自由创造，只要不无理由推翻前两者。

世界硬规则不是固定路线。它决定“事情以什么规律发生”，而不是规定玩家只能做什么。

长期事实也不应无限堆积。只保存未来确实需要延续的身份、关系、经历、物品、承诺、地点、任务及世界状态；纯修辞和一次性细节保留在正文即可。

## 11. 后续实现验收原则

后续每次修改程序、提示词或前端时，应至少检查：

- 是否尊重玩家作为共同作者的路线决定权；
- 是否仍持续维护世界书设定的长期命运；
- 路线变化后，模型是否在寻找自然的命运汇合，而非拒绝玩家；
- 随机事件是否服务当前情节或长期完成度；
- 叙事速度是否真正改变时间与镜头尺度；
- 程序校验是否只保护数据，而没有升级为剧情裁判；
- 写后状态是否只记录正文真实发生的变化；
- 关键人物和事件功能是否可迁移，而非被固定地点和固定顺序绑死。

## 12. 最终原则

> 不要保护故事不受玩家影响；要保护故事的命运能够穿过玩家造成的一切变化。

玩家拥有路线决定权，世界书拥有世界规律与最终命运，规划模型不断重新连接二者，故事模型负责让连接自然发生，程序只提供可靠上下文、状态存储、叙事速度与轻量节奏提示。
