# 成本实测与优化优先级

> 依据：一次真实三回合游玩导出的完整信息（用户提供），以及 DeepSeek 官方[模型与价格](https://api-docs.deepseek.com/zh-cn/quick_start/pricing/)。

---

## 一、实测的三回合 token 结构

| 回合 | planner_pre 输入/命中/输出 | story | planner_post | 合计 |
|---|---|---|---|---|
| 0 | 4650 / 0 / 2354 | 4051 / 0 / 1391 | 3319 / 0 / 4684 | 12020 / 0 / 8429 |
| 1 | 5982 / 3200 / 2039 | 6520 / 2560 / 1651 | 5127 / 1280 / 12693 | 17629 / 7040 / 16383 |
| 2 | 7608 / 3200 / 8923 | 7983 / 2560 / 2562 | 6392 / 1280 / 7397 | 21983 / 7040 / 18882 |

- 输入合计 51,632（命中 14,080 = **27.3%**）
- **输出合计 43,694**（是输入总量的 0.85 倍）
- 回合 1 与回合 2 的命中量**完全相同**（3,200 / 2,560 / 1,280）→ 可缓存前缀已经固定且不再增长，恒为「system 提示词 + STABLE_STORY_CONTEXT」。

## 二、按阶段拆解（三回合累计）

| 阶段 | 输入 | 命中 | 输出 | 思考字符 | 可见输出字符 | 思考/可见 |
|---|---|---|---|---|---|---|
| planner_pre | 18,240 | 6,400 (35%) | 13,316 | 34,310 | 6,677 | 5.1× |
| story | 18,554 | 5,120 (28%) | 5,604 | 6,133 | 4,648 | 1.3× |
| **planner_post** | 14,838 | 2,560 (17%) | **24,774** | **59,324** | 12,206 | **4.9×** |

**planner_post 吃掉了 57% 的输出 token**，而它只做"把写好的正文翻成状态增量"。

## 三、诊断：输出为什么这么大

对同一份导出做逐字段解剖，四种常见成因里只有一种是真因：

| 可能成因 | 检测结果 |
|---|---|
| 模型把收到的 AUTHORITATIVE_STATE 原样回显 | ❌ 无（`out.includes('【')` / `'recent'` 均为 false） |
| 模型把输出模板和示例值抄了回来 | ❌ 无（`create\|update`、`stable-id`、`正文证据` 均不出现） |
| 补丁里数组条目过多 | ❌ 每类 0~3 条，正常 |
| 单条文本字段写得太长 | ⚠️ 有，但只占可见输出 19.5%~26%，且内容有用（`evidenceQuote` 是设计要求的正文原句） |
| **思考本身很长** | ✅ **真因**：思考/可见 = 4.9×，单次调用 36,906 字符思考 |

进一步分析思考内容的构成：

- **不是复读**：句级重复率 0.0%，与输入材料/最终输出的 6-gram 重叠率只有 0.3%~7.8%；
- **是真的在推理**：英文思考，内容是"这名角色是谁、时间线对不对、哪个 beat 动了、这条事实该不该记"；
- **语言不经济**：英文思考同样的逻辑内容比中文耗更多 token；
- **任务被重新推演**：结算阶段在思考里把正文又复述、组织了一遍。

**结论：这是模型自身的行为特征，不是提示词缺了什么。** 用提示词去压（例如规定"必须用中文思考""不要重写正文"）属于对特定模型过拟合，已经撤掉。

## 四、真正决定成本的两件事（按官方价格算）

采用官方定价（元/百万 token），并把三回合实测用量代进去：

| 计费项 | 三回合用量 | 单价（Flash 空闲/高峰） | 三回合花费（空闲 / 高峰） |
|---|---|---|---|
| 缓存命中输入 | 14,080 | 0.02 / 0.04 | 0.0003 / 0.0006 |
| 缓存未命中输入 | 37,552 | 1 / 2 | 0.0376 / 0.0751 |
| 输出 | 43,694 | 4 / 8 | 0.1748 / 0.3496 |
| **合计** | | | **约 0.213 / 0.425 元** |

三点结论：

1. **输出占用 82% 的费用**（0.1748 / 0.213）。全部缓存优化的理论上限只有约 16%（把未命中输入全变成命中：0.0376 → 0.0008），**远小于输出**。
2. **时段差价 2 倍**（空闲时段是高峰时段的一半价格）。高峰时段为北京时间周一至周五 9:00–12:00、14:00–18:00；其余时间（含周末、法定节假日全天）都是空闲价。**同样的玩法，换个时间跑就省一半。**
3. **模型档位差价 3.25 倍**（v4-pro 的输出 13.5/27 对 flash 的 4/8）。

## 五、优化优先级（按可节省的绝对值）

| # | 手段 | 影响 | 代价 |
|---|---|---|---|
| 1 | 避开高峰时段 | **省 50%**（全部费用） | 无（只要换时间玩） |
| 2 | 降低输出的思考量：结算阶段用低档思考强度，或对机械阶段直接关闭思考 | 结算占总输出的 57%，压缩它直接减少最大单项 | 输出质量风险；已做成**逐阶段可调**，默认只给结算降一档 |
| 3 | 按阶段选模型：故事正文用强模型、规划与结算用 flash | 若正文改用 v4-pro，输出单价涨 3.25 倍，需先确认质量收益是否值得 | 需要真实 A/B 才能判断 |
| 4 | 缓存前缀优化 | 上限约 16%（当前命中率 27.3%） | 已完成结构修复；进一步提升需要改动消息结构 |

**优先级 1 不需要改任何代码，却是最大的一项。** 优先级 2 已经落地为可调开关，默认值保守。

## 六、已落地的东西

- **三档思考强度**：DeepSeek 官方映射是 `minimal/low → low`、`medium/high/xhigh → high`、`max/ultra → max`，原先只暴露 high/max，等于把思考预算锁在最贵两档；现在补上 `low`。
- **逐阶段思考强度**（`reasoningEffortByPhase`）：默认只给结算阶段降一档，设置页可对三个阶段分别选择"跟随全局 / Low / High / Max"。
- **关闭思考时显式发送 `thinking: {type:'disabled'}`**：官方文档说明思考模式**默认开启**，"什么都不发"会退回默认开启而不是关闭。
- **缓存前缀结构修复**（见 [`cache-prefix-investigation.md`](cache-prefix-investigation.md)）：结算阶段可复用前缀 34.2% → 67.0%。

## 七、没有做的事（以及为什么）

- **不往提示词里写"用中文思考""不要重写正文"**：那是针对特定模型输出习惯的过拟合，换模型即失效，且会挤占真正要传达的创作约束。
- **不把结算阶段的思考强制关闭**：它确实需要判断（哪条 beat 动了、哪条事实够格进正史），关掉有质量风险。只降一档，并把选择权交给用户。
- **不改三阶段的消息结构去硬凑缓存**：上限只有约 16%，而改动风险覆盖整条链路。
