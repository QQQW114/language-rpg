# 执笔模式随机事件重构计划

> 状态：已弃用（留档）。
>
> 当前故事 Agent 架构会把“长线事件 / 支线事件 / 事件生命周期”并入司辰、事件规划员、叙事导演和故事写手的主链路中处理；本文保留为旧随机事件系统的设计记录，后续若需要重启，应先按新的工具调用与司书库架构重新拆分。

> 目标：先把设计写清楚，后续再集中实现。本文只描述方案与拆分，不直接落代码。

## 核心目标

随机事件不只是「抽到一个小插曲」，而是要能成为服务剧情推进的 **长线情节事件**。

例如当前故事是恋爱线，模型根据上文判断两人关系已经满足条件，于是触发一个动态随机事件：

- 恋爱对象主动邀请主角出去逛街。
- 事件内部包含：
  - 恋爱对象的真正意图。
  - 逛街前的准备。
  - 前往过程。
  - 逛街中遇到的事情。
  - 逛街过程的大体框架与进度。
  - 第 1 回合准备，第 2 回合前往，第 3-7 回合经历主要事件，第 8 回合结束。
  - 事件应在指定回合内收束。

也就是说，动态随机事件一旦触发，不是只在下一回合注入一次，而是会在一段回合内持续给故事模型参考，直到该事件自然完成。

## 总体边界

### 默认行为

- **游历模式**：默认不启用任何随机事件。
- **执笔模式**：默认不启用任何随机事件。

两种模式都不再默认列出书库里的全部随机事件。

玩家需要主动选择：

- 手动生成新的随机事件。
- 手动点击「从书库导入」把书库事件加入当前旅程。
- 手动修改事件内容与触发参数。

### 书库行为

- 动态生成出来的随机事件 / 长线事件会保存到书库。
- 本旅程内也会保留一份触发记录，便于回看与导出。
- 书库中的事件可作为后续旅程的参考素材或直接导入。

## 模式划分

### 模式一：采用随机事件池

这是「固定候选池」模式。

玩家可配置：

- 是否启用随机事件池。
- 点击「从书库导入」选择事件进入当前旅程。
- 点击「生成随机事件」生成候选事件并加入当前旅程。
- 可修改随机事件：
  - 事件名
  - 事件指令
  - 触发起始回合
  - 概率
  - 冷却回合
  - 是否只触发一次
- 可删除 / 隐藏当前旅程内事件。

运行逻辑：

1. 回合结束后，按事件池配置判断下一回合是否触发。
2. 若触发，沿用现有 `RandomEvent.directive` 注入故事模型。
3. 这一路优先复用现有 `randomEventScheduler.ts` 与 `triggeredEvents` 结构。

适用场景：

- 玩家已经写好事件候选。
- 玩家希望事件从固定素材池里按概率出现。

### 模式二：根据剧情动态生成长线随机事件

这是执笔模式重点。

玩家不预先写死具体事件，而是配置一套「动态事件生成规则」。系统在指定回合窗口中调用随机事件模型，让模型根据最近剧情判断是否应该触发事件；若触发，则生成一个较完整的长线事件计划。

玩家可配置：

- 是否启用动态随机事件。
- 开始尝试触发的回合。
- 必定触发区间：
  - 例如：第 5 回合到第 8 回合内必定触发一次。
- 触发后的冷却回合。
- 每回合默认触发概率。
- 每次没有触发后增加的概率。
- 概率上限。
- 动态随机事件提示词：
  - 例：优先参照上文出现的事情、人物、地点、道具、关系变化、未解决情绪。
- 事件偏好提示词：
  - 例：偏恋爱推进 / 偏约会日常 / 偏误会 / 偏伏笔回收 / 偏矛盾升级。
  - 可包含参考随机事件，但不强制照抄。
- 参考随机事件：
  - 从书库导入若干事件作为风格 / 类型参考。

## 动态事件触发逻辑

### 判断阶段

发生在：

1. 某回合故事模型完成。
2. 决策模型完成状态更新。
3. 系统判断下一回合是否处于动态事件检查范围。

检查规则：

- 未到开始回合：不检查。
- 当前已有正在进行的动态事件：通常不生成新事件，除非后续做多事件并行。
- 冷却中：不检查。
- 若当前处于「必定触发区间」，随机事件模型必须判断并生成一个适合当前剧情的事件。
- 否则按当前概率进行检查。
- 如果本轮未触发，累计概率增加 `missProbabilityBonus`。

### 模型判断与生成

动态随机事件模型不是简单根据概率直接生成，而是要结合剧情判断：

- 当前关系是否满足。
- 当前场景是否适合。
- 当前主线是否允许插入。
- 是否能服务玩家给出的事件偏好。
- 是否应该延后，避免破坏节奏。

输入：

- 最近对话。
- 历史摘要。
- 长期一致性记忆。
- 当前 NPC / 背包 / 场景 / 时间 / 天气。
- 未来的伏笔信息（后续添加）。
- 动态随机事件提示词。
- 事件偏好提示词。
- 参考随机事件。

输出：

- 若不触发：输出不触发原因。
- 若触发：输出一个长线事件计划。

### 注入阶段

若触发：

1. 生成事件计划。
2. 保存到书库。
3. 写入当前旅程的「已触发 / 正在进行随机事件」记录。
4. 下一回合开始，把该事件计划作为 `triggeredEvent` 或新的 `activeRandomEventBlock` 注入故事模型。
5. 事件进行期间，每一回合都把事件计划、当前进度、目标结束回合注入故事模型。
6. 到达计划结束回合或模型判断事件已完成后，将事件标记为已完成。

### 失败处理

动态事件生成失败时：

1. 自动重试。
2. 前端沿用当前等待故事 / 决策生成时的样式，例如「故事之笔正在书写」。
3. 重试仍失败后：
   - 记录错误。
   - 不阻塞整个旅程太久。
   - 本轮可跳过事件生成，保持正常故事流程。

## 推荐数据结构

### GameContent

执笔模式创建存档时固化配置：

```ts
authorRandomEvent?: AuthorRandomEventConfig;
```

### AuthorRandomEventConfig

```ts
type AuthorRandomEventMode = 'off' | 'pool' | 'dynamic';

interface GuaranteedRoundRange {
  id: string;
  startRound: number;
  endRound: number;
  consumed?: boolean; // 该区间是否已经成功触发过
}

interface AuthorRandomEventConfig {
  mode: AuthorRandomEventMode;

  // 模式一：事件池
  poolEventIds: string[];
  poolOverrides: Record<string, Partial<RandomEvent>>;

  // 模式二：动态生成
  dynamic: {
    enabled: boolean;
    startRound: number;
    guaranteedRanges: GuaranteedRoundRange[];
    cooldownRounds: number;
    baseProbability: number;
    missProbabilityBonus: number;
    maxProbability: number;
    generatorPrompt: string;
    preferencePrompt: string;
    referenceEventIds: string[];
  };
}
```

### 动态长线事件

建议不要只复用 `RandomEvent.directive`，而是扩展一个运行时结构，再转换为故事模型可读块。

```ts
interface DynamicRandomEventArc {
  id: string;
  name: string;
  summary: string;
  directive: string;
  reason: string;
  trueIntent?: string; // 只给模型看的真实意图，必须注意不要直接剧透给玩家
  involvedNpcIds: string[];
  tags: string[];
  startRound: number;
  targetEndRound: number;
  currentStageIndex: number;
  stages: Array<{
    id: string;
    startRound: number;
    endRound: number;
    title: string;
    goal: string;
    requiredBeats: string[];
    avoid?: string;
  }>;
  status: 'pending' | 'active' | 'completed' | 'cancelled';
  progressNote?: string;
  createdAt: number;
}
```

### GameState

```ts
authorRandomEventState?: {
  pendingEvent?: DynamicRandomEventArc;
  activeEvents: DynamicRandomEventArc[];
  completedEvents: DynamicRandomEventArc[];
  cooldownUntilRound?: number;
  currentProbability?: number;
  lastCheckedRound?: number;
  lastError?: string;
};
```

说明：

- `pendingEvent`：已经生成，准备在下一回合正式注入。
- `activeEvents`：正在进行的长线随机事件。初版建议同时只允许 1 个。
- `completedEvents`：已完成事件，用于右侧面板与导出。
- `currentProbability`：未触发后累计提升的概率。
- `lastCheckedRound`：避免重复检查同一回合。

## UI 设计建议

### 启程页：游历模式

- 默认随机事件列表为空。
- 显示「随机事件」区块。
- 提供：
  - 「生成随机事件」
  - 「从书库导入」
  - 编辑 / 删除 / 勾选事件

### 启程页：执笔模式

显示「随机事件策略」区块：

1. 总开关 / 模式切换：
   - 关闭随机事件
   - 采用随机事件池
   - 根据剧情动态生成

2. 模式一 UI：
   - 当前旅程事件池
   - 从书库导入
   - 生成随机事件
   - 编辑事件
   - 删除事件
   - 概率、触发回合、冷却

3. 模式二 UI：
   - 开始尝试触发回合
   - 必定触发区间，例如 `5-8`
   - 冷却回合
   - 默认概率
   - 未触发概率增加
   - 概率上限
   - 动态随机事件提示词
   - 事件偏好提示词
   - 参考随机事件：从书库导入

### 游戏页右侧面板

新增「随机事件」面板：

- 正在进行的随机事件：
  - 名称
  - 当前阶段
  - 目标结束回合
  - 进度备注
  - 展开后查看完整计划
- 已触发随机事件：
  - 名称
  - 触发回合
  - 完成 / 取消状态
  - 展开后查看完整内容

## 实现拆分建议

### 第一步：修正模式边界

- 游历模式恢复随机事件栏，但默认列表为空。
- 执笔模式隐藏游历模式事件栏，改为「随机事件策略」区块。
- 两种模式都增加「从书库导入」。

### 第二步：补类型与存档迁移

- 新增 `AuthorRandomEventConfig` 类型。
- 新增 `DynamicRandomEventArc` 类型。
- 新增 `authorRandomEventState` 运行状态。
- 老存档 merge 时补默认值。
- 旅程包导入导出自动包含这些字段。

### 第三步：实现事件池模式

- 当前旅程事件池不再默认等于书库全量事件。
- 支持从书库导入。
- 支持生成事件后加入当前旅程并保存到书库。
- 支持编辑触发回合、概率、冷却。
- 游历模式和执笔模式都可复用这部分 UI，但配置入口不同。

### 第四步：实现动态生成长线事件

- 新增 prompt：
  - `src/prompts/authorRandomEventSystem.ts`
- 新增 service：
  - `src/services/authorRandomEventAgent.ts`
- 在 `GamePage` 的故事 + 决策完成后判断下一回合是否需要检查动态事件。
- 若触发，生成 `DynamicRandomEventArc`。
- 写入：
  - 当前旅程 `authorRandomEventState.pendingEvent`
  - 书库随机事件 / 事件素材
- 下一回合故事请求时注入事件计划。

### 第五步：事件进度维护

- 初版可按回合数自动推断当前阶段。
- 后续可让决策模型或记忆模型输出事件进度：
  - 当前阶段是否完成。
  - 是否应提前结束。
  - 是否因玩家选择偏离需要调整计划。

### 第六步：调试与可视化

- 游戏页侧边栏显示 active / completed events。
- 动态事件生成等待时使用当前故事 / 决策等待样式。
- 失败自动重试，最终失败后给出错误提示但不破坏主流程。

## 与未来功能的接口

动态随机事件模型输入中预留：

- 伏笔列表
- 待填坑列表
- 章节蓝图
- 角色目标 / 关系计划
- 逻辑审校结果

这样后续可以让随机事件服务于：

- 伏笔回收
- 人物关系推进
- 节奏调整
- 主线纠偏
- 小说结构稳定性

## 已确认决策

1. 动态事件生成出来后要保存到书库。
2. 游戏页右侧要能查看本旅程已触发 / 正在进行的随机事件。
3. 必定触发支持区间：例如第 X 到第 Y 回合内必定触发一次。
4. 事件生成失败时自动重试。
5. 生成等待样式沿用当前故事 / 决策生成时的等待样式。
6. 游历模式和执笔模式都默认不列出任何书库随机事件，需要手动生成或从书库导入。

## 仍待确认

2. 动态事件结束条件初版是否只按目标回合结束，还是允许模型提前判定完成？
3. 书库中保存动态长线事件时，是扩展现有 `RandomEvent`，还是新增更通用的「事件素材 / 事件弧」类型？
4. 动态事件的隐藏真实意图是否需要在 UI 中默认折叠，避免玩家自己剧透？
