# 双模型故事 Agent 架构（V0.3 重构基线）

> 本文取代当前执笔模式“司辰 + 多 Calls 模型 + Tools 模型 + 司书库自动维护”的主方向。
> 旧文档仅作为实现历史参考；新代码与提示词应优先遵守本文。

## 1. 核心取舍

新架构依赖强模型的理解、规划和工具使用能力，不再用大量专职模型重复判断同一故事问题。

每个常规回合只使用两种模型：

1. **规划 Agent**：同一回合内先规划、后结算，并保持本轮消息与工具上下文。
2. **故事 Agent**：根据简洁写作任务生成正文。

程序负责权威状态、校验、合并、快照和回溯；Agent 不直接修改数据库或司书库文件。

## 2. 标准回合

```text
玩家输入
  ↓
规划 Agent · 写前
  ├─ 读取轻量当前状态
  ├─ 仅在信息不足时搜索/读取历史证据
  └─ 输出 writingBrief
  ↓
故事 Agent
  ├─ 接收 writingBrief 与必要的近期上下文
  ├─ 必要时只读查询上下文
  └─ 输出故事正文
  ↓
规划 Agent · 写后（延续写前会话）
  ├─ 读取最新正文
  ├─ 比较计划与实际发生内容
  └─ 输出经过约束的 statePatch
  ↓
程序校验并提交状态、快照和回合记录
```

规划 Agent 的完整思考历史不跨回合无限累积。每轮永久保存的内容只包括 writingBrief、工具引用、statePatch、回合摘要与调用统计。

## 3. 程序侧权威状态

以下数据必须存储在 `GameState`，不能依赖搜索历史临时推断，也不能由 Agent 直接写文件：

- 背包与能力：新增、消耗、遗失、描述修订。
- 人物实体：稳定 ID、姓名、定位、已知事实、最近出现回合。
- 主角与人物关系：好感等可展示硬值，以及关系状态/近期变化说明。
- 当前场景、时间、天气与可前往场景。
- 活跃任务/事件及其状态。
- 当前故事进度摘要。

搜索工具用于查找证据和恢复长程细节，不替代权威状态快照。

### 3.1 Patch 原则

- 写后仅输出“本轮发生变化”的字段，未出现的状态保持不变。
- 新人物允许 `upsert`；已有角色优先按稳定 ID 更新。
- 好感变化必须有正文依据，单回合增量由程序限幅。
- 道具变化必须能在最新正文中找到获取、消耗、丢失或变化依据。
- 模型返回值必须经过类型、长度、数量和数值范围校验后才能提交。
- 提交失败不破坏旧状态，并保留原始输出供调试。

## 4. 上下文工具

工具收敛为少数通用只读接口：

### `get_story_context`

返回本轮轻量简报：故事摘要、近期回合、当前场景、活跃人物、背包、活跃事件和玩家输入。

### `search_story_context`

按关键词搜索 `history | characters | world | events | items`，返回稳定引用、回合号和短片段。

### `read_story_context`

读取搜索结果对应的原文或实体详情。

首版不向模型开放 `write_doc`、`patch_doc` 或任意数据库写工具。写入只有程序侧的 `commitPlannerPatch`。

## 5. 工具使用纪律

规划 Agent 和故事 Agent 都必须遵守：

1. 优先使用请求中已经提供的最新状态。
2. 只有出现信息缺口、长程回溯、角色身份不确定、设定冲突或明确查证需要时才搜索。
3. 不得为了“更保险”无目标扫描世界书或完整历史。
4. 一次搜索应包含明确关键词和范围；结果足够后立即停止。
5. 通常最多一轮搜索加一轮精确读取；仍不确定时保守写作，不编造硬事实。
6. 搜索结果是证据，不是新的权威状态。

## 6. 角色边界

### 规划 Agent

负责玩家意图、本回合边界、相关事实检索、写作简报、写后状态结算和简洁进度摘要。不负责文学正文。

### 故事 Agent

负责人物表现、对白、场景、节奏和正文质量。不得替玩家完成未授权重大选择，不负责数据库维护。

### 程序

负责状态读写、Schema 校验、数值限幅、实体合并、快照、回溯和 UI 展示。程序不尝试用复杂规则代替模型理解故事。

## 7. 旧架构处置

逐步退役：回合司辰、阶段判断、设定守护、大纲映射、人物规划、场景规划、事件规划、独立导演、逻辑审校、司事和 Agent 自动维护司书库。

保留并改造：

- `storyAgent` → 新故事 Agent。
- `decisionAgent` 的清洗与落库能力 → 规划 Agent 写后 Patch 校验器。
- IndexedDB 回合记录、快照、导入导出。
- 人工维护的世界设定/预设内容。
- 摘要压缩作为低频维护，不参与常规回合的模型种类计数。

## 8. 迁移顺序

1. 新增规划模型设置与双阶段规划服务。
2. 建立通用只读上下文工具。
3. 执笔模式切换为 Planner Pre → Story → Planner Post。
4. 复用现有程序侧 NPC、背包、场景更新函数提交 Patch。
5. 前端调用记录收敛为“写前规划 / 故事写作 / 写后结算”。
6. 删除旧调用链和无引用代码。
7. 最后清理旧文档与司书库自动维护逻辑。
